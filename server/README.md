# 차Park 로컬 기록 서버

외부 의존성 없이 Python 3.9 이상에서 실행한다. 개발용 단일 사용자 저장소이며 인터넷 배포용 서버는 아니다.

```sh
python3 server/app.py
```

`127.0.0.1:8091`에서 수신하며, Pleos 에뮬레이터는 `10.0.2.2:8091`로 연결한다. 첫 실행에 `.local-server/token.txt`와 SQLite DB를 만든다. 토큰과 DB는 Git에서 제외한다. 별도 데이터 경로가 필요하면 `CHAPARK_DATA_DIR`를 설정한다.

서버를 한 번 실행한 뒤 debug APK를 빌드한다. debug 빌드만 로컬 토큰을 읽으며 release는 토큰과 서버 연결을 사용하지 않는다. 토큰을 바꾸면 앱을 다시 빌드해야 한다. 이 debug APK에는 개발용 자격 증명이 포함되므로 공개 배포하지 않는다. HTTP 예외는 debug의 에뮬레이터 호스트에만 적용한다.

## API v1

모든 요청에 `Authorization: Bearer <로컬 토큰>`이 필요하다. API는 이 개발 저장소 전체에 대한 단일 사용자 접근권을 제공한다. 계정·장치 간 권한 분리와 QR 공유는 제공하지 않는다.

| 메서드·경로 | 동작 |
| --- | --- |
| GET `/health` | 상태와 schemaVersion |
| GET `/v1/records` | 삭제되지 않은 `{id,data}` 기록 목록 |
| PUT `/v1/records/{id}` | 완료 기록 snapshot 저장. `placeId` 문자열과 `records` 배열 필수, 최대 1 MB |
| DELETE `/v1/records/{id}` | 기록 본문 삭제 및 삭제 표시 영구 보관 |

동일 ID·동일 JSON 내용 재전송은 200, 동일 ID·다른 내용은 409, 삭제된 ID의 재등록은 410이다. JSON 객체 키 순서는 내용 비교에 영향을 주지 않는다. 배열 순서와 값은 보존한다. 잘못된 본문/ID는 400, 크기 제한은 413, 인증 실패는 401이다.

완료된 기록은 불변 snapshot이다. 변경하려면 새 ID가 필요하며 앱이 자동으로 다른 내용으로 덮어쓰지 않는다. 삭제는 재전송으로 기록이 되살아나지 않도록 tombstone을 남긴다. 로컬 개발 DB를 지우면 서버 기록 및 삭제 표시도 사라진다.

## 앱 동기화

IVI는 DataStore에 기록을 먼저 저장한다. ViewModel이 살아 있는 동안 15초마다 완료 기록과 삭제 목록을 재전송한다. 로컬 archive와 삭제 목록 자체가 영속 재전송 원본이며 별도 성공 큐는 없다. 연결 실패 시 다음 주기에 재시도하고 앱 재시작 후에도 전송한다. 앱 종료 중 실행되는 백그라운드 Worker는 없다.

- 성공: `기기·서버에 저장됨`
- 연결 실패: `기기에 저장됨 · 서버 연결 대기`
- 409/410: `기기에 저장됨 · 서버 기록 충돌 확인 필요`

서버 실패는 기기의 완료 기록을 삭제하지 않는다. 서버에서 다른 기기로 내려받아 병합하는 기능, 활성 계획 동기화, 장소/규칙 API는 아직 구현하지 않았다. 따라서 전체 G1/G2 완료가 아닌 **완료 기록 업로드·삭제 동기화** 범위다.

## 검증

```sh
python3 -m unittest discover -s server -v
```

임시 DB와 임의 loopback 포트를 사용한다. 인증, 형식 검증, 재전송, 충돌, 조회, 반복 삭제, 삭제 후 재등록 차단을 검사한다. `RecordSyncTest`는 실행 중인 개발 서버와 에뮬레이터에서 실제 업로드·조회·삭제를 확인하고 테스트 기록을 삭제한다.

## v2.1.1 확장 (2026-11-13)

위의 업로드 전용 설명은 초기 단계의 기록이다. 현재 추가 계약은 다음과 같다.

| 메서드·경로 | 동작 |
| --- | --- |
| GET `/v1/catalog` | schema 1, 자료 version, ruleVersion, 장소별 좌표·풍경·조건·출처·확인일 |
| GET `/v1/rules` | `v211-1`과 번들 규칙의 호환 계약. 외부 실행 코드를 받지 않음 |
| GET `/v1/plans/{id}` | 활성 계획의 revision과 data, 없음 404·삭제 410 |
| PUT `/v1/plans/{id}` | `{baseRevision,data}`. 같은 내용 재시도는 revision 유지, 변경은 +1, 불일치 409 |
| DELETE `/v1/plans/{id}` | 본문 제거·삭제 표식 유지 |
| GET `/v1/records` | 기록과 `deleted` ID 목록. 삭제는 다운로드에도 전파 |

앱은 활성 계획도 업로드하고 완료 기록은 추가 병합한다. 같은 ID의 다른 기록은 자동 덮어쓰지 않는다. 계획 충돌에서는 사용자가 확인해 기기 계획을 새 ID로 보관할 수 있고 서버 원본은 유지한다. 완료 기록 충돌은 표시만 하고 원본을 보존한다. 서버 활성 계획을 다른 기기에 내려받아 여행을 재개하는 UI와 계정 간 병합은 아직 제공하지 않는다.

자료는 AtomicFile로 검증 후 캐시하며 새 여행 경계에서만 적용한다. 호환 규칙 버전, 중복 ID, 좌표 범위, HTTPS 출처를 검사하고 오래된/근거 없는 허용 조건은 UNKNOWN으로 낮춘다. 조회 실패는 번들/마지막 정상 자료로 이어간다. 실시간 충전기 가용성·현장 조망 데이터는 없다. release는 로컬 토큰과 네트워크 동기화를 제외한다.
