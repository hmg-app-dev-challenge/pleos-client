# v2.1 첫 개발 단계

2026-11-12 · A1~A4 중 여행 조건·출발 관문·저장 확장을 구현했다. 전체 v2.1 완료를 의미하지 않는다.

## 변경한 동작

- IVI에서 1~2명 제한을 없애고 인원을 증감한다. 3명 이상이면 추가 잠자리 검토, 모든 인원에 대해 침구·매트 수량을 제시한다. 인원 변경으로 의미가 달라진 체크만 해제한다.
- 배터리 확인 기준은 0~100%에서 5% 단위로 조절한다. 기준 미만일 때 충전 검토를 제안하며, 같은 값일 때는 미만으로 처리하지 않는다. 차량의 충분한 잔량·취침 가능 시간은 판단하지 않는다.
- 다음 날 철수 예정 시각을 0~23시에서 한 시간 단위로 선택하고 저장한다. 아직 날짜·시간대 기반의 절대 종료 시각이나 일출 계산에는 연결하지 않았다.
- 출발 전 행동·짐은 모두 확인해야 이동 단계로 넘어간다. UI 비활성화 외에도 공통 reducer가 건너뛰기를 차단한다. 현장 운영 안내는 도착·주차 후 수면 준비에서 확인하며 확인 전 다음 단계로 넘어가지 않는다.
- IVI 저장 스키마를 2로 올리고 인원·기준·철수 시각·SOC 출처·선택적 수신 시각을 저장한다. 스키마 1의 진행·체크를 유지하고 기존 fixture 출처를 예시로 구분한다. 과거에 수집하지 않은 관측 시각은 null이다.
- 이전 가상 장소의 진행 중 여행을 새 여행으로 초기화하지 않는다. 실제 좌표가 없는 목적지의 내비 요청은 실패 안내와 장소 재선택으로 처리한다.
- 제품의 배터리는 아직 로컬 예시 값이다. 화면에 작은 예시 라벨을 붙였으며 실제 SDK SOC 연결은 B1~B2 작업이다.
- 폰도 공유 출발/현장 체크·인원 규칙을 반영했다. 폰에서 배터리 기준·철수 시각을 편집하는 UI는 이번 IVI 우선 작업에 포함하지 않았다.

## 검증

JVM 테스트 23개 통과. 가족 3명, 기준 경계, 유효하지 않은 조건, 체크 무효화, 출발 관문과 현장 분리, 기존 내비·주행 제한 전이를 포함한다. [JVM 결과](verification/v21-stage-a/unit-tests.txt)

Pleos IVI 기기 테스트 9개 통과. 3인·40% 기준·다음 날 9시 입력과 Activity 복원, 짐 체크 후 실제 내비 연결·복귀·현장 체크·철수, 스키마 1 변환과 스키마 2 왕복 저장, 좁은 창 양 테마를 검증했다. [IVI 결과](verification/v21-stage-a/ivi-tests.txt)

폰 기기 테스트 3개도 통과했다. 양 APK 빌드 및 Lint 오류 0(기존 경고 폰 8·IVI 9)을 확인했다.

## 남은 작업

A1의 여행 ID·날짜·시간대·확인 시각·사건/기록/동기화 전체 계약, A2의 해당 모델 저장, A3의 날짜 기반 종료 시각은 남아 있다. A4의 출발/현장 체크 분리는 구현했다. 다음은 남은 데이터 계약을 보완하고 SOC 단위·구독·오류 구분을 검증해 B1~B2로 연결한다. 자동 마이그레이션의 중간 프로세스 종료·실제 파일 손상 복구 추가 검증도 남아 있다.
