# v2.1.1 상세 변경 검토

검토일 2026-11-13. 사용자 제공 [v2.1.1 원문](reference/CHAPARK_PROPOSAL_V2_1_1.md)(작성 기준 2026-11-12)을 [v2.1.0 원문](reference/CHAPARK_PROPOSAL_V2_1_0.md), 현행 코드 및 저장된 검증 결과와 비교했다. 줄바꿈·강조·목록 확장은 기능 추가와 구분했다. 이번 작업은 문서 개정이며 앱 구현·SDK 승인·외부 사실 재검증을 의미하지 않는다.

## 실질 변경과 반영 위치

| --- | --- | --- |

## 유지되는 핵심 요구

가족 3명, 지역·경험·인원에 제한 없는 대상 정의, 사용자 SOC 기준, 인원별 침구와 추가 잠자리, 출발 전 짐 싣기 관문은 기존 요구다. 바다/산/강 후보, 필수 조건 이후 풍경 태그, 계산 시각과 조사 조망 방향의 분리, 이동·충전 시간 미확보 시 권장만 표시, 충전소 경유 포함 실제 내비 안내, 주행 잠금, 따뜻한 밤 모드와 해의 시간 배경, 오프라인 기록 및 다음 여행 재안내도 새로 추가된 것으로 계산하지 않는다.

대표 시나리오의 17:20·15:30은 예시이며 자동 채울 데이터가 아니다. ‘차량용 커튼’은 시나리오에서 사용자가 빠뜨렸다고 기록할 준비물이고 모든 사용자에게 고정 추천할 데이터가 아니다. 기록 카드 QR·사진·폰/계정·음성·직접 제어는 확장이다.

## 에너지 검증 표현의 정밀화

원문의 ‘읽기 지원 속성 확인’은 에뮬레이터 VHAL의 READ/CONTINUOUS 등록을 뜻한다. 앱 읽기 허용 또는 실차 가용성을 뜻하지 않는다. [기존 진단](EV_PROPERTY_REVIEW.md)에 따라 다음 수준을 보존한다.

| 구분 | 확인 결과 | 허용되는 해석 |
| --- | --- | --- |
| 공개 SOC API | 제품 BatterySession 연결, Console 20%와 조회값 일치 증거 | 해당 에뮬레이터에서 공개 API SOC 값을 받음. 연속 변화·오류 전체 통과는 아님 |
| EV_BATTERY_LEVEL 직접 접근 | VHAL 등록, 앱 SecurityException | 앱 직접 값 미수신. SOC 퍼센트와 구분 |
| EV_BATTERY_INSTANTANEOUS_CHARGE_RATE 직접 접근 | VHAL 등록, 앱 SecurityException | 전력값 미수신. 0W/미지원으로 치환하지 않음 |
| deprecated Pleos energy getter | 원시 Float 77400.0 수신 | 직접 AAOS 읽기 성공은 아님. 단위 대조 전 제품 계산 금지 |
| 권한 | Pleos 에너지 권한과 android.car 에너지 권한이 별개 | 기존 권한의 승인을 다른 권한 승인으로 확장하지 않음 |
| 기술지원·실차 | 문의 초안 미발송, 개별 검토 답변 및 실차 검증 없음 | 지원 확정·승인 완료로 표시하지 않음 |

확장 추정은 기술지원 절차와 실차 지원 범위를 확인한 후에만 검토한다. 허용될 경우에도 단위·부호·freshness·동시 수신·최근 표본 안정성 및 목표 SOC에 대응하는 사용 가능 에너지 검증이 먼저다. 명목 용량×SOC를 검증 없이 적용하거나, 현재 SOC 하나로 예상 시간을 만드는 우회는 범위 밖이다.

## 지표 변경과 출처 관리

새 MAU 산식은 **차박 이용 인구 × 전기차 비율 × Pleos Connect 탑재 비율 × 앱 설치율 × 월 활성 비율**이다. 비율은 앞 단계 집단에 대한 조건부 비율로 정의하는 것이 개발·분석 설계 제안이다. 전기차 등록 대수와 총인구처럼 서로 다른 단위를 직접 결합하지 않는다. 계획된 Pleos 보급량은 현재 탑재율로 사용하지 않는다.

원문 인용 목록: 33.7%, 예약 불필요 응답 15.0%→28.1%, 장소 유형 48.6%/21.1%/14.6%, 국내 EV 누적 100만 대, 2030년 Pleos 약 2천만 대. 이번에는 원문의 주장과 출처 표기를 보존했으며 외부 원문을 다시 확인하지 않았다. 제출 전 공식 원문 URL·발행일·표/페이지·모집단·기준 연도를 검증하고, 근거가 없는 MAU 숫자는 작성하지 않는다.

재사용률은 다음 차박을 실제 떠난 사람 중 재사용 비율이다. 같은 여행의 다음 날 앱 실행은 재사용이 아니다. 완주율은 여행 단위이며 준비부터 철수·기록 생성까지를 본다. 기존 비교 실험의 시간·누락·조작 횟수·확신, 입문자/경험자 각각 3~5명 인터뷰는 유지한다. 인터뷰 계획은 핵심 구현 완료 조건과 별도다.

## 현재 구현과의 주요 차이

- 홈에 금요일 퇴근·회사 주차장 문구가 남아 있어 토요일 가족/집 앞 대표 시나리오와 불일치한다. 실제 사용자 상황을 고정하지 않는 문구로 수정할 계획이다.
- 장소 3곳은 지도 좌표가 있는 서울 캠핑장이다. 바다/산/강 조건 검증과 조망 조사 완료로 볼 수 없다.
- 공개 SOC 제품 연결은 구현됐다. 미지원 카드 숨김·정차 중 수동 입력·오류 코드별 대응은 마무리가 필요하다.
- 실제 Car UX 기반 잠금과 debug 우회 제거는 구현됐다. 주행 상태 전환 행렬은 추가 검증 대상이다.
- NOAA 근사 계산·따뜻한 테마는 구현됐다. 정확도 기준값 대조·시간 배경·계산 사건 영속 저장은 남아 있다.
- 기록 조회/삭제·누락 준비물 재안내와 로컬 서버 업로드는 구현됐다. 한 장의 기억 카드, 모든 미확인 조건의 다음 여행 연결, 장소 근거 스냅샷, 계획/캐시 동기화는 남아 있다.
- 4단계 날짜 누락 복구 및 라이트/다크/밤 팝업·입력 글자색은 수정·회귀 검증됐다. 후속 작업에서 유지해야 할 인수 조건이다.
