# 차Park v2.1 개발 실행 계획

2026-11-12 · 기준: [제품 기획 v2.1](PRODUCT_SPEC_V2_1.md) · Android 1명 / 서버 1명 기준 작업 분담.

기존 IVI·공통 모델·DataStore·NaviHelper 연결을 확장한다. v2.1 첫 개발 묶음은 [작업 기록](V21_STAGE_A.md)에 정리했으며, 아래 완료 표시는 기존 코드와 검증 증거가 있는 부분에만 사용한다. 문서 개정은 앱 버전이나 기능 완료를 의미하지 않는다. 기존 날짜별 일정 대신 의존성과 인수 조건을 기준으로 진행하며 실제 제출 마감 확인 후 달력 일정으로 환산한다.

## 2026-11-12 추가 진행

사용자 승인에 따라 기존 서버 없이 로컬 개발 서버를 구현했다. [로컬 서버·기록 연동 검증](V21_LOCAL_SERVER.md)에 현재 코드와 증거를 정리했다. 아래 초기 기반 표는 착수 당시 비교이며, 최신 상태는 단계 표와 작업 기록을 따른다.

## 공통 모델과 저장 설계

아래 이름은 신규 구현 제안이며 현재 존재하는 클래스라고 보지 않는다.

- `VehicleReading`: 값, 원시값, 정규화 단위, capability, 상태, 출처(vehicle/manual/emulator/example), 앱 수신 시각, 제공되는 경우 센서 시각. 출처와 지원 상태를 별도로 관리한다.
- `TripPlan`: 안정적 여행 ID, 여행 날짜·시간대, 인원, 취사, 종료 시각, 사용자 SOC 확인 기준, 장소·경유지 선택, 규칙 버전. 기존 반려동물·침낭 조건 유지.
- `PlaceEvidence`: 속성별 값·근거 URL·확인일·확인 주체, 대표 좌표/차량 진입구, 주차/숙박/화장실/취사, 풍경 태그·조망 방위. 충전소는 위치 외 커넥터·이용 조건·정보 출처를 갖고 실시간 가용성 미확인은 별도 표시.
- `PreparationItem`: stable ID, 의미/규칙 버전, 수량, 출발 전/짐/현장 단계, 사용자 확인 내용·시각. 현장 항목을 일괄 출발 관문에 넣지 않는다.
- `NavigationAttempt`: 목적지·순서 있는 경유지, generation, 요청/탐색/안내/실패 상태와 실제 SDK 관측, 시간 정보의 단위·측정 시각.
- `SolarEvent`: 장소·날짜·시간대, 계산 시각·방위·계산 버전. 장소 조사와 조합한 안내는 근거를 함께 참조.
- `TripRecord`: 계획·장소 근거·규칙의 당시 스냅샷, 실제 사건 및 계산 사건의 타입별 타임라인, 출발·철수 SOC, 체크·충전 판단·누락 준비물. 안전 점수나 보증으로 변환하지 않는다.
- `SyncOperation`: 여행/기록 ID, 로컬 revision, idempotency key, 대기/전송/실패 상태. 서버 갱신이 사용자 체크나 기록을 조용히 덮어쓰지 않도록 충돌 정책 적용.

활성 여행 DataStore는 유지한다. 여러 여행의 기록·outbox·장소 캐시는 Room 도입을 우선 검토하고 A1에서 확정한다. 기존 저장소 스키마 1 → 2 전환은 기본값으로 새 여행을 만들어 덮어쓰지 않는다. 과거 데이터에 없던 시각·출처·배터리는 null/미수집으로 보존한다. 폰과 공유 모델 변경 시 폰의 상태 복원·규칙 회귀를 확인한다.

인증·장치 식별·접근 범위·보관/삭제 정책은 G1의 필수 설계 항목이다. 계정 연동이 확장이라는 이유로 여행 기록 API를 공개 쓰기/읽기로 제공하지 않는다. 서버 제공자·새 외부 서비스 생성은 아직 선택하지 않는다. QR 공유는 접근 범위·만료·공유 해제를 포함한 확장 작업으로 분리한다.

## SDK 및 디자인 확인 관문

첨부 기획서의 API 목록은 구현 요구와 검증 후보로 취급한다. `requestRouteWithWaypoints`, `RequestWaypointInfo`, `onTripInfo`, Brake/DrivingMode 신호 및 각 권한은 고정된 AAR·공식 문서·런타임으로 확인한 계약만 코드에 넣는다. SDK 제공 상태는 My Project에서 재확인한다. 지원하지 않는 기능을 코드에서 추정해 호출하지 않는다.

NaviHelper 단일 목적지는 이미 검증했다. 현재 에뮬레이터에서는 배경 지도 타일이 회색이며 자동 이동 재생은 검증되지 않았다. 원인 조사와 제공 내비 앱 환경 확인을 H1의 통합 이슈로 남긴다. 실제 도착 이벤트 분기는 구현돼 있으나 기존 전체 흐름 검증의 도착은 사용자 확인이다.

기존 Pleos Figma 시스템의 색상·Asta Sans·타입·버튼·선택·팝업을 재사용한다. 기록 카드·풍경 태그·태양 배경·따뜻한 밤 테마는 앱 고유 확장이므로 원본 컴포넌트라고 주장하지 않는다. 구현 시 Figma 원본을 다시 대조하고 상태별 매핑과 대비·가로/좁은 창 검수를 남긴다. 출처 라벨은 표시하되 개발용 조작·시연 배너는 사용자 화면에 넣지 않는다.

## 완료 보고 기준

핵심 요구 R01~R13에 대해 구현 경로·테스트·화면 증거를 연결한다. 조건부 SDK 기능은 확인한 가용성과 대체 흐름을 기록한다. 폰·QR·직접 제어·음성은 핵심 완료의 필수 조건에 넣지 않는다. release APK·영상·저장소 정보는 실제 산출물로만 채우고, 기획 버전 2.1을 APK 버전 또는 배포 완료로 표시하지 않는다.
