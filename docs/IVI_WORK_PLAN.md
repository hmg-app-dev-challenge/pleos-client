# 차Park 1차 MVP 개발 실행 계획 — PRD v0.2 반영

2026-11-14 · 제품 기획 v2.1.1 + [MVP PRD v0.2](reference/CHAPARK_MVP_PRD_V0_2.md) · 기준 앱 IVI 0.4.0 (`8a3e3b0`). 현재 구현 진행은 아래 상태와 [실행 기록](MVP_V0_2_EXECUTION.md)을 따른다. 새 PRD 전체 인수는 아직 완료되지 않았다.

기능 범위는 PRD를 적용하되 **시각 디자인은 사용자가 지정한 기존 현대차 Pleos 디자인 시스템을 우선**한다. [상세 차이·결정 대장](MVP_PRD_V0_2_REVIEW.md), [목표 화면 흐름](PRODUCT_FLOW_PLAN.md), [현재 구현](IMPLEMENTATION_STATUS.md)을 함께 본다. 이전 A~H 작업과 증거는 [이전 계획](history/20261114_before_mvp_prd_v02/IVI_WORK_PLAN.md), [실행 이력](V2_1_1_EXECUTION.md)에 보존한다.

## 이번 MVP의 범위와 우선순위

1. 사용자 진행을 **차박 계획 → 출발 준비 → 이동 → 차박 → 철수와 기록**의 5단계로 통합한다. 홈은 단계 밖, SDK·로딩·오류는 내부 상태다.
2. IVI 가로 화면에서 조건과 장소를 함께 다루고 최소 3개 후보를 비교한다. Pleos 토큰·Asta Sans·버튼·선택·팝업·Light/Dark 상태를 재사용한다.
3. 취사 3종, 인원별 수량, 필수/선택/누락, 장소별 충전 후보와 실제 내비 전환을 PRD 규칙에 맞춘다.
4. 기존 여행 복원·체크 보존·불변 기록·사용자 데이터 삭제 방지를 유지한다. 1차 release는 로컬만으로 완주하며 서버 고도화가 제출을 막지 않는다.
5. 새 release에서 대표 흐름과 AC-01~10을 검증한다. 기존 7단계 debug 시험과 release 첫 실행은 새 인수의 대체 증거가 아니다.

원문의 미정값은 [D-01~10 대장](MVP_PRD_V0_2_REVIEW.md)에 남긴다. 출처 없는 장소 조건·조망·충전 시간은 시나리오에 맞춰 만들지 않는다. 첨부 문서의 공개 전환·업로드·접수 메일 항목은 실제 실행 승인으로 보지 않는다.

## 단계별 구현과 커밋 단위

2026-11-14 현재 V02-01은 **부분 구현**이다. 취사 3종·준비 상태·단계 매핑·저장 마이그레이션 기반을 구현했고 정책 확정/입력 상태 정리는 남아 있다. V02-03도 부분 구현이다(5단계 표시·계획 탭·가로 장소 비교·홈 이어하기). V02-05는 누락 표시/취소·필수 관문·지난 누락 그룹·기록 표시를 구현했고 기본 준비·취사 조합·인원 수량 분리를 추가했고 최종 필수/선택 정책 인수는 남아 있다. V02-04/06은 난지 지역 충전 후보 관계·SOC 조건별 검토·기존 선택 명시 해제를 부분 구현했다. 다른 장소 자료 확충과 전체 경유 인수는 남아 있다. V02-06/07은 현장·수면 6개/철수 5개 및 과거 기준 보존, 당시 정보의 불변 기록 요약을 추가했다. 자동 일몰 밤 모드와 원시 전달 결과 세분화는 후속이다. V02-02/08은 계획 상태다. [실행·시험 근거](MVP_V0_2_EXECUTION.md)를 따른다. 구현할 때 각 행의 완료 조건을 확인한 뒤 독립 커밋으로 남긴다. 데이터 조사와 정책 결정의 미확보를 코드 완료로 숨기지 않는다.

V02-01의 준비 상태는 `PENDING / COMPLETED / OMITTED` 등 동등한 표현을 사용하되 `required`와 분리한다. 정차에서만 변경할 수 있다. 조건 변경으로 사라진 항목의 과거 누락은 사건 기록으로 보존하고 새 준비 목록과 혼동하지 않는다.

## 기존 저장과 신호를 옮기는 규칙

- 기존 step 0은 홈, 1/2는 PLANNING, 3은 PREPARING, 4는 MOVING(도착·주차 상태에 따라 STAYING 내부 확인으로 복원), 5는 STAYING, 6은 철수/기록 화면으로 매핑한다. step 6만으로 `completed=true`를 만들지 않는다.
- enum 이름을 강제하지 않는다. 단일 여행 상태에서 표시 단계와 내비/도착/주차/철수 사실을 분리한다. 완료 archive는 재계산하지 않는다.
- Condition `ALLOWED ↔ CONFIRMED`, `RESTRICTED ↔ NOT_ALLOWED`, `UNKNOWN ↔ UNKNOWN`을 명시적으로 변환한다. 저장된 이름 변경만으로 값이 사라지지 않게 한다.
- Source `SDK ↔ VEHICLE`, `EMULATOR`, `MANUAL`, `UNKNOWN ↔ UNAVAILABLE`. 기존 DEMO는 예시로 계속 식별하고 차량값으로 변환하지 않는다. capability, reading status, 원시값/단위, 마지막 정상 수신 시각은 별도 유지한다.
- 날짜 기본 오늘은 새 여행에만 적용하고 이미 저장된 날짜/시간대를 덮어쓰지 않는다. 과거 날짜 누락은 복구 안내를 유지한다. 분 단위 철수 입력 도입 여부에 맞춰 endHour를 명시적으로 변환한다.
- 새 규칙/카탈로그의 schema·rule version을 함께 올리고 호환되지 않는 다운로드는 기존 정상 번들/캐시로 복귀한다. 폰은 확장 범위지만 공유 모델 컴파일/저장 회귀는 필수다.

새 페이지에서도 기존 컴포넌트를 조합한다. PRD의 카드/탭 제안으로 색상·서체·치수를 새로 만들지 않는다. 2560×1440 시스템/1682×1210 앱 창과 800dp 좁은 창, 큰 글자, 긴 출처, 선택·비활성·눌림·오류·팝업을 Light/Dark 및 밤 상태로 검수한다. 밤의 따뜻한 확장은 본문 대비를 낮추거나 시스템 밝기/차량 조명을 제어하지 않는다. 원본에 없는 카드/배경은 앱 확장으로 기록한다. 화면의 주요 CTA는 하나이며 보조 비교·출처·뒤로 동작은 보조 위계로 둔다.

## 제출과 제외 사항

실행 가능한 release APK와 새 환경의 전체 흐름을 확인한 다음 `apk/차박차박_차Park_release.apk`라는 제출 복사본, SHA-256, 최종 커밋, README 환경/미구현 범위, 검증 영상을 준비한다. 이전 데스크톱 0.4.0 APK는 기준 산출물이며 새 PRD 완료본으로 이름만 바꾸지 않는다. 릴리스 번호는 실제 코드 변경·검증 후 정한다.

서버/G1·G2는 기존 구현을 보존하는 개발 보조 범위로 낮춘다. 새 서버 배포·계정·QR, 폰 확장, 음성, 차량 직접 제어, 인터뷰는 Later다. 조건부 C-01~04의 미지원은 각각 대체 UX/미노출로 처리한다. 예상 사용시간은 기존 X1~X3 지원·권한·실차 데이터 검증 관문 전 구현하지 않는다. 저장소 공개·접수 메일·외부 업로드·지원 문의 발송은 별도 요청 없이 실행하지 않는다.
