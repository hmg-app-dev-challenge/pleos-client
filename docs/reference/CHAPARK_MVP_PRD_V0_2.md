## 1. 제품 개요

### 1.1 한 줄 정의

차Park는 차박 여행을 떠나는 전기차 운전자가 장소의 이용 조건과 차량에서 읽은 배터리 상태를 함께 확인해 준비하고, 길 안내부터 철수 후 기록까지 한 흐름으로 이어 가는 Pleos 차량 앱이다.

### 1.2 해결하려는 문제

- 차박 장소의 주차·차내 숙박 가능 여부, 야간 화장실, 취사 조건, 충전소 정보의 분산
- 차량 배터리 상태와 장소 조건을 사용자가 직접 연결해야 하는 문제
- 준비 목록 확인, 차량 내비게이션 목적지 입력, 도착 후 차량 설정의 분리
- 여행 종료 후 확인 내용과 누락 준비물이 다음 여행에 남지 않는 문제

### 1.3 핵심 사용자

- Pleos Connect 탑재 전기차 운전자
- 처음 방문하는 차박 장소의 조건과 현재 차량 상태를 함께 확인하려는 사용자
- 차박 경험 수준, 지역, 동행 형태와 무관한 공통 준비 수요 보유자

### 1.4 핵심 가치

1. 차량에서 읽은 SOC와 장소 조건을 준비 행동으로 연결
2. 준비 결과를 차량 내비게이션의 실제 길 안내로 연결
3. 주행·정차 상태에 맞춘 정보량과 조작 방식 제공
4. 준비부터 철수까지의 과정을 한 장의 기록으로 연결

## 3. 차량 디스플레이 기준 사용자 흐름

차Park는 스마트폰 앱이 아니라 차량 중앙 디스플레이에서 실행되는 가로형 차량 앱이다. 사용자가 인지하는 진행 단계는 5개로 제한한다. SDK 확인, 체크리스트 완료 여부, 내비게이션 요청 결과와 같은 기술 상태는 각 단계 내부 상태로 처리하며 별도의 사용자 단계나 화면으로 만들지 않는다.

```text
1. 차박 계획
   차량 SOC 확인 → 여행 조건 입력 → 장소 비교 및 선택

2. 출발 준비
   조건 기반 준비 안내 → 짐 싣기 체크

3. 이동
   목적지·충전소 경유지 확인 → 기본 차량 내비게이션으로 전환

4. 차박
   앱 복귀 → 도착 확인 → 수면 준비 → 밤 모드

5. 철수와 기록
   설정·장비 회수 확인 → 하룻밤 기록 카드 생성
```

### 3.1 사용자 진행 단계

| 단계 | 사용자 목적 | 진입 조건 | 완료 조건 |
|---|---|---|---|
| `PLANNING` | 오늘 갈 장소와 여행 조건 결정 | 새 차박 시작 | 장소 선택 완료 |
| `PREPARING` | 준비 안내 확인과 짐 싣기 | 장소 선택 완료 | 필수 준비 항목 완료 |
| `MOVING` | 차량 내비게이션으로 이동 | 경로 요청 및 내비게이션 전환 | 사용자의 도착 확인 |
| `STAYING` | 도착 후 차량과 잠자리 준비 | `도착했어요` 선택 | 다음 날 철수 시작 |
| `COMPLETED` | 철수 확인과 여행 기록 | 필수 철수 항목 완료 | 기록 카드 생성 |

진행 중인 여행이 없는 상태는 홈 화면의 기본 상태일 뿐 사용자 진행 단계에 포함하지 않는다. 실제 코드에 동일한 enum을 반드시 만들 필요는 없지만, 앱 재진입 시 현재 단계와 입력값을 복원할 수 있는 단일 여행 상태는 유지한다.

### 3.2 화면 구성

| 화면 | 진행 단계 | 핵심 역할 | 주요 행동 |
|---|---|---|---|
| 홈 | 단계 진입 전 | SOC·진행 중 여행·새 차박 시작 표시 | `새 차박 시작`, `이어하기` |
| 차박 계획 | `PLANNING` | 여행 조건 입력과 장소 3곳 비교·선택 | `이 장소 선택` |
| 출발 준비 | `PREPARING` | 준비 안내와 짐 싣기 체크 | `준비 완료` |
| 경로 확인 | `MOVING` 진입 | 목적지·충전소 경유지 최종 확인 | `차량 내비게이션 시작` |
| 차박 모드 | `STAYING` | 도착 후 수면 준비와 밤 모드 | `수면 준비 완료`, `철수 시작` |
| 철수·기록 | `COMPLETED` | 철수 체크와 기록 카드 표시 | `철수 완료`, `새 여행 시작` |

여행 조건 입력과 장소 비교를 각각 독립된 여러 화면으로 쪼개지 않는다. 차박 계획 화면 안에서 좌측 조건 영역과 우측 장소 카드 영역 또는 2개 탭을 사용한다. 정확한 배치는 실제 Pleos 화면 규격에 맞추되, 화면 수를 늘리는 방식으로 해결하지 않는다.

### 3.3 차량 디스플레이 공통 원칙

- 차량 중앙 디스플레이의 가로형 화면 기준
- 키보드 입력보다 큰 선택 버튼·칩·카드 중심
- 한 화면의 주요 행동 1개 원칙
- 장소 3곳을 한 화면에서 비교할 수 있는 가로 카드 우선
- 긴 세로 스크롤과 스마트폰식 다단계 폼 최소화
- 내비게이션 전달 후 차Park 자체 주행 화면을 유지하지 않고 기본 차량 내비게이션으로 전환
- 내비게이션 또는 다른 차량 화면에서 차Park로 복귀해도 선택 장소·조건·체크 상태 유지
- 주행 중 차Park로 복귀하면 현재 여행 요약만 표시하고 계획·비교·체크 조작 비활성화
- 운전자와 동승자를 구별할 수 있다고 가정하지 않음
- 현재 상태와 다음 행동 중심의 짧은 문구 사용

## 4. 공통 데이터 정의

### 4.1 차량 상태 VehicleState

| 필드 | 타입 | 필수 | 설명 |
|---|---|---:|---|
| `soc` | Number 또는 null | Y | 현재 배터리 잔량. 조회 실패 시 null |
| `socSource` | Enum | Y | `VEHICLE`, `EMULATOR`, `MANUAL`, `UNAVAILABLE` |
| `socUpdatedAt` | DateTime 또는 null | Y | 마지막 정상 수신 시각 |
| `socCapability` | Enum | Y | `NONE`, `READ`, `WRITE`, `READ_WRITE`, `UNKNOWN` |
| `isDriving` | Boolean 또는 null | Y | 주행 여부. 확인 실패 시 null |
| `driveStateSource` | Enum | Y | `VEHICLE`, `EMULATOR`, `UNAVAILABLE` |

#### 표시 규칙

- 실제 SDK 수신값: `차량 값` 또는 `에뮬레이터 값` 표시
- 사용자 입력값: `직접 입력` 표시
- 조회 실패: 숫자 대신 `배터리 정보를 불러오지 못했어요` 표시
- 이전 수신값 사용 시: 마지막 갱신 시각 표시
- 예시 데이터: 실제 차량 값처럼 표현 금지

### 4.2 여행 조건 TripCondition

| 필드 | 타입 | 필수 | 규칙 |
|---|---|---:|---|
| `peopleCount` | Integer | Y | 1명 이상. 최대값은 결정 필요 |
| `cookingPlan` | Enum | Y | `NONE`, `SIMPLE`, `COOKING` |
| `checkoutTime` | Time | Y | 다음 날 목표 철수 시각 |

`peopleCount`는 준비물 수량 조정을 위한 사용자 입력값이다. 실제 차량 탑승 인원을 감지하거나 검증하지 않으며, 차량 정원 또는 취침 가능 인원을 판단하지 않는다.

## 5. 화면 및 기능 상세

## F-01 앱 실행과 차량 상태 확인

### 목적

현재 차량에서 사용할 수 있는 기능을 확인하고 SOC를 준비 안내에 사용할 수 있는 상태로 만드는 기능.

### 진입

- 앱 최초 실행
- 사용자의 `새 차박 시작` 선택
- 차량 연결 재시도

이 기능은 별도의 진행 화면이 아니라 홈 화면의 차량 상태 영역과 로딩·오류 상태로 표현한다.

### 처리 순서

1. `checkEvBatteryStateOfChargeCapabilities` 호출
2. 결과가 `READ` 또는 `READ_WRITE`이면 SOC 조회
3. SOC 변화 구독 등록
4. Brake 또는 DrivingMode Capability 확인
5. 모든 결과를 VehicleState에 저장
6. 화면에 값의 출처와 마지막 갱신 시각 표시

### 상태별 동작

| 상태 | 화면 결과 | 사용자 행동 |
|---|---|---|
| SOC 정상 수신 | SOC 숫자와 출처 표시 | 여행 조건 입력으로 이동 |
| SOC 읽기 미지원 | `이 차량에서는 배터리 조회를 지원하지 않아요` | 직접 입력 또는 SOC 미사용 진행 |
| 권한 부족 | `차량 정보 접근 권한이 필요해요` | 재시도 또는 직접 입력 |
| 서비스 연결 실패 | `차량 연결을 확인한 뒤 다시 시도해 주세요` | 재시도 |
| 값 형식 오류 | 실제 값으로 표시하지 않음 | 오류 안내 및 직접 입력 |

### 예외 원칙

- `100` 등 수신 원시값의 단위를 검증하지 못한 경우 `%`를 임의로 붙이지 않음
- 에뮬레이터에서 검증된 값은 `에뮬레이터 값`으로 표시
- 실패 값을 0으로 대체 금지
- 무한 로딩 금지. 제한 시간 이후 실패 상태 표시

### 완료 조건

- SOC 정상값 또는 대체 상태가 확정된 경우 완료
- Capability 결과와 SOC 출처가 로그에 남는 경우 완료

## F-02 여행 조건 입력

여행 조건 입력은 독립된 여러 화면이 아니라 `차박 계획` 화면의 조건 영역에서 처리한다. 한 번에 모든 값을 키보드로 입력시키지 않고 큰 선택 버튼과 시간 선택 컴포넌트를 사용한다.

### 입력 항목

1. 함께 차에서 잘 인원
2. 취사 계획
3. 다음 날 목표 철수 시각
4. 충전 경유 검토 기준 SOC
5. 여행 날짜

### 입력 규칙

- 필수값 누락 시 `장소 보러 가기` 비활성화
- 인원은 준비물 수량에만 사용
- 취사 계획은 장소의 취사 조건과 준비 목록에 사용
- SOC 기준은 안전 보장 기준이 아닌 `충전 경유를 검토할 시점`으로 안내
- 현재 SOC를 읽지 못한 경우 직접 입력 선택 제공
- 직접 입력값은 `직접 입력` 출처 표시

### 결정 필요

- 인원 선택의 최대값
- SOC 기준 선택 범위와 기본값
- 철수 시각 입력 방식: 직접 시간 선택 또는 시간대 버튼

### 완료 조건

- 입력한 값이 장소 선택 이후에도 유지
- 이전 화면 복귀 후 값 보존
- 앱 재시작 시 여행 진행 상태 복구 여부는 MVP에서 선택 사항

## F-03 장소 비교 및 선택

### 기본 화면

- 차량 가로 화면에서 장소 3곳을 좌우로 비교할 수 있는 카드 배치
- 최소 3개 장소 카드 표시
- 카드 필수 정보: 장소명, 지역, 야간 화장실, 주차, 차내 숙박, 취사, 주변 충전소, 풍경 태그, 확인일
- `UNKNOWN`은 `확인 필요`로 표시
- 카드 선택 시 같은 화면의 상세 패널 또는 전체 폭 상세 영역 표시
- 필수 정보를 확인하기 위해 새로운 화면을 연속으로 추가하지 않음

### 필터 규칙

- 사용자가 특정 조건을 선택한 경우에만 해당 조건으로 필터링
- `확인 필요` 장소를 자동으로 허용하거나 제거하지 않음
- `확인된 장소만 보기` 선택 시 `UNKNOWN` 장소 제외
- 결과가 없으면 빈 화면 대신 제외된 조건 표시

### 장소 상세

- 장소 조건별 출처와 확인일 표시
- 일몰·일출 시각과 해의 방위 표시
- 조망 방향이 확인된 경우에만 해의 방위와 비교 문구 표시
- 조망 방향이 없으면 일몰·일출 시각과 방위만 표시
- `이 장소 선택` 버튼 제공

### 일몰·일출 계산

- 입력: 장소 좌표, 여행 날짜
- 출력: 일몰 시각, 일출 시각, 각 시점의 방위
- 계산 실패 시 해당 영역만 `계산할 수 없음` 표시
- 실제 풍경, 날씨, 시야 확보를 보장하는 문구 금지

### 완료 조건

- 장소 하나를 선택하면 `selectedPlaceId` 저장
- 이전 장소 선택은 새 선택으로 교체
- 선택 장소의 출처와 확인일이 다음 화면에서도 확인 가능

## F-04 조건 기반 준비 안내 생성

### 입력

- VehicleState
- TripCondition
- 선택한 Place
- 이전 기록의 누락 준비물 목록

### 기본 생성 결과

준비 결과는 다음 세 그룹으로 구성한다.

1. `챙길 것`
2. `출발 전 할 일`
3. `현장에서 할 일`

### MVP 규칙표

| 조건 | 생성 또는 변경 결과 |
|---|---|
| 기본 | 장소 조건 재확인, 휴대폰 충전, 식수, 쓰레기 회수 용품 추가 |
| `peopleCount = N` | 매트 N개, 침구 N세트 표시 |
| `cookingPlan = NONE` | 취사 장비 미표시 |
| `cookingPlan = SIMPLE` | 간편식·식수 항목 표시 |
| `cookingPlan = COOKING` + 장소 취사 허용 | 취사 장비·식재료·정리 용품 표시 |
| `cookingPlan = COOKING` + `NOT_ALLOWED` | 취사 장비 제거, `취사 불가 장소예요. 식사 계획을 바꿔 주세요` 표시 |
| `cookingPlan = COOKING` + `UNKNOWN` | `취사 가능 여부를 출처에서 다시 확인해 주세요` 표시 |
| 야간 화장실 `CONFIRMED` | 일반 표시 |
| 야간 화장실 `UNKNOWN` | `야간 운영 여부 확인 필요` 경고와 다른 장소 비교 버튼 표시 |
| 야간 화장실 `NOT_ALLOWED` | `야간 화장실 이용 불가` 경고와 다른 장소 비교 버튼 표시 |
| `soc < socReviewThreshold` | `충전 경유 검토` 행동 카드 표시 |
| SOC 없음 | 충전 필요 여부 판단 금지, `SOC를 확인하지 못해 충전 경유를 판단할 수 없어요` 표시 |
| 이전 누락 준비물 존재 | `지난번에 빠뜨린 준비물` 그룹을 최상단 표시 |

### 중요 규칙

- `soc == socReviewThreshold`이면 충전 경유 검토 카드 미표시
- SOC 기준은 사용자의 확인 기준이며 충분한 배터리를 보장하지 않음
- 준비 항목이 추가된 이유를 사용자에게 표시
- 서로 충돌하는 조건에서는 제한 조건을 우선 적용
- 취사 불가 장소에서 취사 장비를 그대로 표시하지 않음

### 완료 조건

- 입력 하나가 바뀌면 결과가 즉시 다시 계산
- 같은 입력은 항상 같은 결과 생성
- 조건에 없는 항목을 AI가 임의 생성하지 않음

## F-05 짐 싣기 체크리스트

### 화면 구성

- 준비 그룹별 체크리스트
- 전체 진행률 `완료 수 / 전체 필수 항목 수`
- 각 항목의 추가 이유 표시 가능
- `준비 완료` 버튼

### 동작 규칙

- 필수 항목을 모두 체크하기 전 `준비 완료` 비활성화
- 선택 항목은 진행률 계산에서 제외
- 체크 상태는 화면 이동 후에도 유지
- 사용자가 항목을 `이번에는 챙기지 못함`으로 표시 가능
- 챙기지 못한 항목은 기록 카드와 다음 여행 준비 목록에 저장

### 완료 조건

- 필수 항목 전체 완료 시 경로 확인 화면 진입 가능
- 누락 처리된 항목이 기록 데이터에 포함

## F-06 충전소 경유 검토와 NaviHelper 전달

### 충전 경유 카드 노출 조건

`soc`가 존재하고 `soc < socReviewThreshold`인 경우에만 노출한다.

### 사용자 흐름

1. `충전 경유 검토` 카드 선택
2. 선택 장소에 연결된 충전소 후보 표시
3. 사용자가 충전소 하나를 선택하거나 `경유하지 않기` 선택
4. 경로 확인 화면에서 목적지와 경유지를 최종 확인
5. 경유지 선택 시 `requestRouteWithWaypoints` 호출
6. 경유지 미선택 시 `requestRoute` 호출
7. 길 안내 시작을 확인하면 기본 차량 내비게이션으로 전환

### 결과 상태

| 결과 | 화면 처리 |
|---|---|
| 요청 성공 | `차량 내비게이션으로 경로를 보냈어요` 표시 |
| 안내 시작 확인 | `길 안내가 시작됐어요` 표시 후 기본 차량 내비게이션으로 전환 |
| 요청 실패 | 주소, 재시도, 충전소 다시 선택 제공 |
| NaviHelper 미지원 | 주소 복사 또는 화면 표시. 성공으로 처리 금지 |

### 완료 조건

- 목적지 좌표가 선택 장소와 일치
- 경유지 사용 시 선택한 충전소 좌표 포함
- 요청 성공과 실제 안내 시작을 구분
- 실패 상태에서 앱 흐름 중단 없이 재시도 가능
- 내비게이션 전환 전 선택 장소·조건·체크 상태 저장

---

## F-07 차량 내비게이션 전환과 앱 복귀

### 기본 원칙

- 이동 중 길 안내의 주체는 차Park가 아니라 기본 차량 내비게이션
- 차Park 내부에 독립적인 지도·경로 안내·상시 주행 화면을 구현하지 않음
- NaviHelper 전달 성공 후 사용자를 기본 차량 내비게이션으로 전환
- 내비게이션에서 차Park로 돌아오면 `MOVING` 단계의 여행 요약 복원

### 앱 복귀 시 표시 정보

- 현재 여행 단계 `이동 중`
- 목적지명과 선택한 충전소 경유지
- 현재 SOC와 값의 출처
- `도착했어요` 버튼은 정차 상태에서만 활성화
- 정차 후 이어 할 작업인 `도착 후 수면 준비` 안내

### 주행 중 차Park가 다시 열린 경우

- 현재 여행 요약만 표시
- 장소 비교, 조건 변경, 체크리스트 수정 비활성화
- 비활성 항목 선택 시 `정차 후 이어서 사용할 수 있어요` 표시
- 사용자가 입력한 값과 체크 상태 유지
- 운전자와 동승자를 구별하지 않으므로 동승자용 예외 조작 제공 금지

### 주행 상태 확인 실패

- `isDriving = null`이면 안전 우선으로 주행 중과 동일한 제한 적용
- 사용자가 임의로 정차 상태를 선택해 제한을 해제하는 기능 미제공

### 완료 조건

- 길 안내 시작 후 기본 차량 내비게이션으로 전환
- 다른 차량 화면을 거쳐 앱으로 복귀해도 선택 장소·조건·체크 상태 유지
- 주행 중 상세 조작 제한, 정차 확인 후 현재 단계 복원

## F-08 도착 후 수면 준비와 밤 모드

### 진입

- 사용자의 `도착했어요` 선택
- 또는 주행 종료 후 도착 확인 선택

### 수면 준비 항목

- 공조 설정 확인
- 실내등 설정 확인
- 환기 방법 확인
- 문 잠금 확인
- 개인 준비물 정리 확인

차량 상태를 실제로 읽을 수 있는 항목만 자동 상태로 표시한다. 조회하지 못한 항목은 사용자가 직접 조작 후 체크한다.

### 밤 모드

- 어두운 배경과 낮은 대비의 따뜻한 색상 적용
- 주행 중 자동 적용 금지
- 장소 좌표와 날짜로 계산한 일몰 시각 이후 밤 배경 표시
- 계산 실패 시 사용자가 밤 모드를 직접 선택 가능
- 화면 밝기나 차량 조명을 직접 제어하지 않음

### 완료 조건

- 수면 준비 체크 상태 저장
- 밤 모드 진입·해제 가능
- 차량 제어를 수행하지 않았다면 `설정 완료`가 아니라 `사용자 확인 완료`로 기록

## F-09 철수 체크와 기록 카드

### 철수 항목

- 차량 설정 원복 확인
- 실내·외 장비 회수 확인
- 쓰레기 회수 확인
- 놓고 가는 물품 확인
- 출발 전 장소 상태 확인

### 기록 카드 필드

| 영역 | 내용 |
|---|---|
| 장소 | 장소명, 풍경 태그, 정보 확인일 |
| 시간 | 여행 날짜, 일몰·일출 시각 |
| 차량 | 출발 SOC, 철수 SOC, 각 값의 출처 |
| 준비 | 완료 항목 수, 누락 준비물 |
| 이동 | 충전소 경유 여부, 내비게이션 전달 결과 |
| 현장 | 수면 준비 확인 여부, 철수 완료 여부 |
| 타임라인 | 장소 선택 → 준비 → 출발 → 도착 → 일몰 → 일출 → 철수 |

### 기록 원칙

- 사용자가 실제로 확인한 내용만 기록
- 숙박·안전·배터리 충분 여부를 증명하는 표현 금지
- SOC를 읽지 못한 경우 빈값 또는 `확인하지 못함` 표시
- 누락 준비물은 다음 여행의 준비 안내 최상단에 표시

### 완료 조건

- 필수 철수 항목 완료 후 기록 카드 생성
- 기록 카드 재조회 가능
- 새 여행 시작 시 이전 여행 상태와 혼합되지 않음

## 6. 오류 및 대체 처리

| 오류 유형 | 사용자 메시지 | 대체 행동 |
|---|---|---|
| SDK 미지원 | `이 차량에서는 해당 기능을 지원하지 않아요` | 기능 비활성화 또는 직접 입력 |
| 권한 부족 | `차량 정보 접근 권한이 필요해요` | 재시도·기능 없이 진행 |
| 서비스 연결 실패 | `차량 연결을 확인해 주세요` | 재연결 |
| 주행 제한 | `정차 후 이용할 수 있어요` | 입력 상태 보존 |
| 장소 정보 미확인 | `확인 필요` | 출처 열기·다른 장소 비교 |
| 내비게이션 전달 실패 | `경로를 보내지 못했어요` | 재시도·주소 표시 |
| 일몰 계산 실패 | `일몰 정보를 계산하지 못했어요` | 해당 정보 없이 진행 |
| 기록 저장 실패 | `기록을 저장하지 못했어요` | 재시도·임시 상태 유지 |

오류 메시지는 실패 원인과 사용자가 다음에 할 행동을 함께 제공한다. 모든 실패를 동일한 토스트 메시지로 처리하지 않는다.

## 7. 비기능 요구사항

### 7.1 차량 UI

- 차량 중앙 디스플레이의 가로형 화면과 실제 Pleos 화면 규격 기준
- 한 화면의 주요 행동 1개 원칙
- 큰 글자, 큰 터치 영역, 선택 버튼 중심의 조작
- 키보드 입력과 긴 세로 스크롤 최소화
- 장소 비교는 한 화면의 가로 카드 또는 분할 영역 우선
- 색상만으로 상태를 구분하지 않는 아이콘·텍스트 병행
- 긴 설명보다 현재 상태와 다음 행동 중심의 문구
- 기본 차량 내비게이션 전환과 앱 복귀 이후에도 입력 상태 보존
- 운전자와 동승자를 구별할 수 있다고 가정하지 않는 동일한 주행 제한 적용

### 7.2 안정성

- SDK 호출 실패로 앱 종료 금지
- null 차량 값 처리
- 중복 구독 방지 및 화면 종료 시 구독 해제
- 경로 요청 중 중복 버튼 입력 방지
- 기록 카드 중복 생성 방지

### 7.3 데이터와 개인정보

- 계정 기능은 1차 MVP 범위에서 제외 가능
- 사용자 이름·전화번호·정확한 이동 이력의 외부 전송 금지
- 로컬 또는 서버 저장 여부를 README에 명시
- 예시 장소와 차량 값의 데이터 출처 표시

## 8. 대표 시연 시나리오

### 시나리오 조건

| 항목 | 데모 값 |
|---|---|
| 사용자 | 차박이 처음인 전기차 운전자 |
| 인원 | 3명 |
| 취사 계획 | 취사 희망 |
| 장소 후보 | 3곳 |
| 선택 장소 | 서해안 일몰 장소 |
| 선택 장소 조건 | 야간 화장실 확인, 취사 불가, 바다 조망 방향 확인 |
| SOC | Virtual Console로 기준 미만 값 설정 |
| 목표 | 조건 변화가 준비 안내와 내비게이션 경유지에 반영되는 장면 시연 |

### 시연 순서와 기대 결과

1. 차박 계획
   - 앱 실행 후 SOC 에뮬레이터 값과 출처 표시
   - 인원 3명·취사 희망·철수 시각 입력
   - 같은 계획 화면에서 장소 3곳 비교
   - 야간 화장실 `확인 필요` 장소와 확인된 장소의 차이 표시
   - `바다×일몰` 장소 선택 후 일몰 시각·방위·조망 방향 표시
2. 출발 준비
   - 매트 3개·침구 3세트 표시
   - 취사 불가로 간편식 계획 변경 안내
   - SOC 기준 미만으로 충전 경유 검토 카드 표시
   - 완료 전 출발 버튼 비활성화, 완료 후 활성화
3. 이동
   - 충전소 선택 및 NaviHelper 전달
   - 경유지 포함 경로 요청 결과 표시 후 기본 차량 내비게이션으로 전환
   - 차Park 복귀 시 이동 중 여행 요약과 저장된 조건 표시
   - 주행 중에는 상세 조작 비활성화, 정차 후 `도착했어요` 활성화
4. 차박
   - 안내형 차량 설정 체크와 밤 모드 표시
5. 철수와 기록
   - 출발·철수 SOC, 충전 경유, 준비 누락, 일몰·일출 타임라인을 포함한 기록 카드 생성

## 9. 인수 조건 Acceptance Criteria

### AC-01 SOC 변화 반영

```gherkin
Given SOC 읽기를 지원하는 에뮬레이터에서 앱을 실행한 상태
When Virtual Console의 SOC 값을 변경
Then 앱의 SOC 표시가 갱신
And 값의 출처가 에뮬레이터로 표시
```

### AC-02 SOC 기준 미만 처리

```gherkin
Given 사용자의 충전 검토 기준이 T이고 현재 SOC가 T 미만인 상태
When 준비 안내를 생성
Then 충전 경유 검토 카드 표시
And 도착 SOC·귀가 가능 여부·공조 가능 시간 미표시
```

### AC-03 SOC 기준과 같은 값 처리

```gherkin
Given 현재 SOC가 사용자의 충전 검토 기준과 같은 상태
When 준비 안내를 생성
Then 충전 경유 검토 카드를 자동 표시하지 않음
```

### AC-04 취사 불가 장소 처리

```gherkin
Given 사용자가 취사를 선택하고 장소의 취사 상태가 NOT_ALLOWED인 상태
When 장소를 선택
Then 취사 제한 경고 표시
And 취사 장비 준비 항목 제거
And 대체 식사 계획 안내 표시
```

### AC-05 장소 정보 미확인 처리

```gherkin
Given 장소의 야간 화장실 상태가 UNKNOWN인 상태
When 장소 카드를 표시
Then 허용 또는 이용 가능으로 표시하지 않음
And 확인 필요와 출처 표시
```

### AC-06 체크리스트 완료 조건

```gherkin
Given 필수 준비 항목 일부가 완료되지 않은 상태
When 사용자가 출발을 시도
Then 준비 완료 버튼 비활성화
When 모든 필수 항목을 완료
Then 준비 완료 버튼 활성화
```

### AC-07 내비게이션 요청 구분

```gherkin
Given 목적지와 충전소 경유지를 선택한 상태
When 내비게이션 전달 실행
Then requestRouteWithWaypoints 호출
And 요청 성공과 안내 시작 상태를 구분해 표시
```

### AC-08 내비게이션 전환과 앱 복귀

```gherkin
Given 목적지 또는 경유지 포함 경로 요청에 성공한 상태
When 차량 내비게이션의 길 안내 시작을 확인
Then 기본 차량 내비게이션으로 전환
When 사용자가 차Park로 다시 복귀
Then 이동 중 여행 요약 표시
And 기존 장소·조건·체크 상태 유지
And 주행 중이면 상세 조작 비활성화
```

### AC-09 밤 모드 제한

```gherkin
Given 차량이 주행 중인 상태
When 계산된 일몰 시각이 지남
Then 밤 모드를 자동으로 적용하지 않음
When 차량이 정차하고 사용자가 수면 모드를 선택
Then 밤 모드 적용
```

### AC-10 기록 카드 정확성

```gherkin
Given 철수 필수 항목을 완료한 상태
When 기록 카드를 생성
Then 선택 장소·출발 및 철수 SOC·각 값의 출처·충전 경유·누락 준비물 포함
And 확인하지 못한 값을 임의 숫자로 채우지 않음
```

## 10. AI 구현 지침

1. 이 문서에 정의되지 않은 기능·화면·값·기준의 임의 추가 금지
2. 결정 필요 항목을 개발자가 임의 확정하지 않고 질문 또는 상수 분리
3. `CONFIRMED`, `NOT_ALLOWED`, `UNKNOWN` 상태의 boolean 단순화 금지
4. 차량 값·직접 입력·에뮬레이터 값·예시 값의 출처 혼합 금지
5. SDK 호출 성공과 실제 기능 적용 성공의 동일 처리 금지
6. SOC 조회 실패를 0%로 처리 금지
7. 안전·숙박·배터리 충분 여부에 대한 보장성 문구 추가 금지
8. Conditional 기능 실패가 핵심 흐름 전체를 차단하지 않도록 구현
9. 기존 화면을 수정할 때 입력값과 여행 진행 상태 보존
10. 스마트폰식 세로 화면·다단계 폼·독립 주행 지도 화면 임의 추가 금지
11. 기본 차량 내비게이션으로 전환한 뒤 앱 복귀 상태 검증
12. 구현 후 각 기능 ID와 인수 조건별 테스트 결과 보고
