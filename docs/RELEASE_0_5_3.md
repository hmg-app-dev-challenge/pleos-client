# IVI 0.5.3 — 안내 응답 단절 처리

2026-11-14 · versionCode 6 · 저장 스키마 11 유지. V02-06/08의 안내 상태·복귀 경계를 보완했다.

## 문제와 변경

이전에는 처음 연결할 때만 30초 제한이 있었다. 안내가 시작된 뒤 SDK의 응답이 끊겨도 예외가 발생하지 않으면 오래된 `GUIDING` 표시가 남을 수 있었다.

- 안내 상태, 목적지, 선택한 충전 경유지의 수신 시각을 각각 관리한다. 필요한 응답 중 하나라도 30초 이상 오래되면 안내 확인을 해제하고 재시도 가능한 실패 상태로 전환한다. 2초 조회 주기와 앱 전경 복귀 시 검사한다. 30초는 앱의 상태 유효성 정책이며 SDK의 응답 보장 시간이 아니다.
- 시스템 날짜 변경에 영향받지 않는 단조 증가 시계를 사용한다. SDK 콜백 도착 시각을 보관하므로 메인 스레드에서 늦게 처리된 응답을 새 응답으로 간주하지 않는다. 한 종류의 응답만 계속 와도 다른 종류의 단절을 숨기지 않는다.
- 목적지·안내·필요 경유지 모두 최근 응답인 경우에만 GUIDING이나 경유 확인 상태를 확정한다. 오래된 상태를 바탕으로 자동 도착 또는 경유 수동 확인을 처리하지 않는다.
- 실패 시 SDK 관찰만 해제한다. 차량 내비의 경로를 취소하거나 자동으로 새 경로를 요청하지 않는다. 선택한 여행·경유지·준비 체크를 유지하고 기존 재시도 동작을 사용한다.
- 기존 화면·Pleos 디자인 토큰·색상·서체는 유지했다.

검증은 기존 Pleos Release AVD에서 수행했다. 시스템 앱 비활성화나 네트워크 설정 변경을 하지 않았다. 테스트가 수정한 활성 여행은 보관/복원하며, SDK 경로 시험은 난지캠핑장과 테스트 충전 경유지를 사용한다. 기존 앱 위에 0.5.3을 설치하고 차Park가 전면에 표시되는 것을 확인한 뒤 CPU 부하를 피하려고 AVD를 일시정지했다.

**위 시험은 실제 네트워크 단절·복구 검증이 아니다.** 실제 SDK와 주입한 응답 나이 경계를 구분한다. 사용자 재시도 없이 FAILED 여행을 자동 복구하는 기능도 추가하지 않았다. 재부팅 없는 네트워크 복구, 실차 서비스 단절/권한·EV 잔여시간, 대표 장소 운영·조망 근거 3곳은 계속 남아 있다.
