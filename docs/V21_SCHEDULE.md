# 여행 일정과 저장 구조 확장

2026-11-12 · v2.1 A1~A3 후속 개발.

## 구현

- 여행 날짜와 IANA 시간대를 명시적으로 저장한다. IVI의 오늘 날짜로 계획 버튼은 기기 시간대를 함께 선택하고, 날짜를 앞뒤로 변경할 수 있다. 기기 시간대를 적용하는 별도 동작도 제공한다.
- 철수 예정은 여행 날짜 다음 날의 선택한 시각을 기준으로 절대 시각(Instant)으로 계산한다. 월말·연말에도 다음 달력 날짜를 사용한다. 새 여행을 시작할 때 이전 여행 날짜는 초기화한다.
- 일광절약시간 전환으로 해당 현지 시간이 없거나 두 번 생기면 null을 반환하고 출발을 막는다. 자동으로 한 시간 밀거나 임의 오프셋을 선택하지 않는다. 다른 철수 시각을 선택하면 해결할 수 있다.
- 날짜 미선택 시 출발 관문을 통과하지 못한다. 이전 단계에서 날짜를 선택하라는 안내를 표시한다. 폰에도 오늘 날짜 선택과 저장 복원을 연결했다. 폰의 임의 날짜/시간대 편집 UI는 아직 IVI와 동등하지 않다.
- IVI 저장 스키마 3에 날짜·시간대·여행 ID를 보존한다. 스키마 1/2의 날짜는 미수집으로 남기고, 기존 진행·체크는 보존한다. 과거 관측 시각을 임의로 생성하지 않는다.
- IVI 새 여행과 초기화에 새 ID를 부여하고 저장/재실행 시 유지한다. 기존 ID 없는 여행에는 마이그레이션 시 식별자만 부여한다. 이는 사건 발생 시각을 추정하는 기능이 아니다.

## 검증

JVM 테스트 27개 통과. 연말 날짜 경계, 서울 시간대의 절대 철수 시각, 뉴욕 DST 공백/중복 시각, 잘못된 날짜·시간대, 미해결 시각의 출발 차단 및 체크 보존을 포함한다.

IVI 관련 기기 테스트 4개 통과: 전체 여행·내비 복귀, 스키마 이전 데이터 변환, 날짜/시간대/ID 왕복 저장, 좁은 창 양 테마. 실제 기기 테스트는 기존 Pleos Connect 에뮬레이터에서 수행했다.

## 다음 작업과 경계

확인 시각·실제 이동 사건·기록 카드·서버 동기화 모델은 아직 남아 있다. 출발 시각 추천·일몰/일출 계산도 이번 단계에 포함하지 않았다. 실제 SOC 공급자는 아직 연결하지 않았으며 제품의 배터리는 예시 라벨을 유지한다.

EV_BATTERY_LEVEL과 순간 충·방전률의 직접 접근은 [속성 검토](EV_PROPERTY_REVIEW.md)에 기록된 기술 지원 검토 상태를 유지한다. 문의 메일은 아직 발송하지 않았으며 이번 재개를 발송 승인으로 해석하지 않았다. 해당 검토와 독립적으로 공개 SOC API 검증 및 기록 기반 작업을 이어갈 수 있다.
